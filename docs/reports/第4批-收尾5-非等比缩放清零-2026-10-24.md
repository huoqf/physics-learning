# 第4批·收尾5 — 非等比缩放清零（20 → 0）

> 日期：2026-10-24
> 范围：上一批扫描暴露的 20 页 `[VectorArrow] sceneScale 非等比缩放` 告警。
> 结果：**20 页 → 0 页；全库 124 页「完全无告警」从 95 页升到 114 页。**
> 剩余 10 页告警是既有的 KaTeX Unicode-in-math 与 `<rect>` 属性错误，与本批无关（集合与改前完全一致）。
> **复核修订**：初版把 `doppler-effect`、`forced-resonance` 判为 B1，经复核上调为 B2 并做等比锁定（见 4.3）。

---

## 一、先补一条判据：非等比到底会「错」在哪里

`VectorArrow` 的绘制是 `dir = normalize(vector)`，直接用数据方向乘像素长度 —— **箭头方向本身不受 scaleX/scaleY 影响**。
真正被非等比破坏的只有两件事：

1. 经 `worldToDesign` 换算的**几何位置与形状**（矩形被拉长、圆变椭圆、间距比例失真）；
2. 以世界坐标给的**箭头起点**（终点按方向推出去） → 起点落在被拉伸后的几何上，箭就不再指向它「应该指向」的对象。

所以判据不是「有没有告警」，而是「本页有没有 world 驱动的几何」。
配套实测：所有 20 页的 `<circle>` 渲染宽高比**全部为 1.000**（圆都是用像素半径画的），
也就是说「圆变椭圆」在这批页面里实际一个都没有发生 —— 判断落在第 2 条上。

## 二、A 类：12 页，锚点 viewport → design（画面零变化）

判据（逐页核查依赖树，全部满足才改）：`worldToDesign/worldToPixel` 引用 0 次、`origin={` 裸用 0 次
（全走 `originDesign`）、`.scaleX/.scaleY` 引用 0 次。

| 页 | 原 scaleX / scaleY |
|---|---|
| friction | 1 / 2.40 |
| gravity-basic、vector-addition、orthogonal-decomposition、gravity | 1 / 1.22 |
| work、energy-conservation、velocity、acceleration、uniform-acceleration、connected-bodies | 1 / 1.13 |

### 2.1 一个连带陷阱：`maxVectorLength` 在两个分支上不等价

`useSceneScale` 的默认上限：`viewport` 分支取**可视区短边** × 0.3，`design` 分支取**preset 短边** × 0.3。
中屏可视区比 preset 高得多（实测 840×736 vs 840×650），于是：

- `full` 页：220.9 → 195（箭头整体缩 12%）
- `splitV` 页（friction / uniform-acceleration）：220.9 → 97.5（**缩到 44%，肉眼可见**）

首轮改完截图对比证实了这点（friction 的 F_N 从 85 px 掉到 37 px）。
为此在 `useSceneScale` 里导出唯一真源 `defaultMaxVectorLength(w, h)`，A 类页显式传入
`defaultMaxVectorLength(vp.designVisibleW, vp.designVisibleH)`，把改前的取值**原样冻结**。

### 2.2 验证方式：逐页前后截图做像素级比对

12 页各截同参数、同时刻（t=0）的完整界面，逐张比对：

- **10 页像素级完全一致**（二进制相同）
- 2 页有差异：`vector-addition` 88 像素 / 最大通道差 5，`uniform-acceleration` 18 像素 / 最大通道差 6
  —— 差异区域都在右侧面板（x≈1400、x≈1175），是文字抗锯齿级的抖动，场景区域 0 差异

## 三、B1 类：5 页，显式标记有意非等比

这些页面要么几何是「铺满分区」的示意图形，要么矢量只有水平/竖直方向，实测各向异性在 3%~17%：

| 页 | 量程 | 实测 scaleX/scaleY | 各向异性 | 依据 |
|---|---|---|---|---|
| gas-laws、clapeyron | 3.0×5.0 m（420×650） | 140 / 130 | 7.7% | 气缸是示意尺寸，体积读数取自面板；矢量仅竖直 |
| saturated-vapor | 10×4 m（840×325） | 84 / 81.25 | 3.4% | 同上；分子用像素半径 |
| electrostatic-shielding | 10×8 m（840×650） | 84 / 81.25 | 3.4% | 场强箭头全水平；导体是圆角矩形（非球） |
| brownian-motion | 100×150 | 4.2 / 4.96 | 17% | 花粉/分子像素半径；轨迹是随机路径，无对照基准 |

处理：保留 `physicsWidth/physicsHeight` 原值，加 `intentionalNonUniformScale: true` + 逐页写明实测值与理由。

> 初版把 `doppler-effect`、`forced-resonance` 也归到这里，经复核上调为 B2（见 4.3）——
> 它们的问题是**「圆用单轴比例尺、配套几何走双轴」的跨元素失配**，只看圆自身的宽高比是看不出来的。

## 四、B2 类：3 页确有几何变形 —— nuclear-decay / doppler-effect / forced-resonance

### 4.0 nuclear-decay（镜头级变形）

`10.0 m × 6.5 m`（1.54）塞进 splitV 的 840:325（2.58）→ `scaleX = 84、scaleY = 50`，**纵向拉伸 68%**。

后果链：原子核位置经 `worldToDesign` 换算（纵向间距放大 1.68 倍，几个核的排布被拉长成竖条），
而库仑斥力箭头方向取自数据向量 → 箭头**不再指向被拉伸后的邻核**，正是「斜向矢量与几何错位」。

修法（与 `system-isolated` 同一套）：

```ts
const fitScale = Math.min(vp.designVisibleW / W, vp.designVisibleH / H)   // 两轴都装得下的最小值
physicsWidth : vp.designVisibleW / fitScale
physicsHeight: vp.designVisibleH / fitScale
```

世界量程随之等比放大（内容永不裁切），`scaleX === scaleY === fitScale`。改后告警消失，
核的排布恢复等比、箭头重新指向邻核。

### 4.1 其余 B 类页为什么没改

- **圆变椭圆**：实测 20 页的圆渲染宽高比全为 1.000 —— 没有一页真发生（都按像素半径绘制）。
- **斜向矢量错位**：镜头级的变形只有 nuclear-decay 一页（有斜向矢量 + 矢量指向被 world 换算的邻接对象）。
  gas-laws / saturated-vapor / electrostatic-shielding 的矢量全是水平或竖直，非等比不改变方向；
  brownian 的 F合 是合力方向（不沿轨迹），轨迹本身也没有可对照的几何基准。
  （另有 doppler-effect / forced-resonance 属于跨元素失配，见 4.3。）

### 4.2 边界判断（可随时推翻）

`brownian-motion`（17%）是这批里最接近临界的一页。若要求绝对统一，只需一行 `anchor: 'design'`
（`physicsWidth/physicsHeight` 本就按 preset 宽高比取值，改锚点后 `scaleX === scaleY`），
代价是画面内容按 17% 等比缩小（多出来的竖直空间变成留白）。
本批按「无可对照的几何变形」判为 B1，未做此改动。

### 4.3 复核后上调的两页：跨元素失配（初版漏判）

初版只量了 `<circle>` 自身的渲染宽高比（全为 1.000）就放行，漏掉了一种更隐蔽的失配：
**圆心/半径用单轴比例尺画成正圆，而与它配套的几何（切线、销钉、槽体）走 `worldToDesign` 的双轴换算**。
两者比例尺不等时，各元素自身都「正常」，但相互之间对不上。

**`doppler-effect`（马赫锥与波前圆脱节）**
`DopplerWavefrontScene.tsx`：波前圆半径 `w.radius * sceneScale.scaleX`（19.54），
而模式 2 的激波切线 `machCone.upperLine/lowerLine` 走 `worldToDesign`（X 19.54 / Y 18.06）。
实测「圆心到切线的距离 − 半径」= 1.1 / 1.8 / 2.5 / 3.1 / 3.8 / **4.5 px**（随半径变大而累积）。
修法：`physicsHeight` 不再写死 36，改由 `48 × 可视高/可视宽` 反推 → `scaleX === scaleY`。
改后同一测量 = **0 / 0 / 0 / 0 / 0 / 0 px**（严格相切）。且模式 0 改前改后截图**逐像素 0 差异**
（波前圆与声源都在 y=0 轴上，只有模式 2 的锥体受影响），默认视图零风险。
注：本页不能用 `anchor: 'design'` —— 48:36 = 1.333 ≠ 840:650 = 1.292，锚在 preset 上仍有 3.2% 非等比。

**`forced-resonance`（轮盘正圆 vs 曲柄销椭圆轨道）**
`ForcedResonanceScene.tsx`：轮盘半径 `wheelRadius * sceneScale.scale`（= min(100,113.2)=100，画正圆），
曲柄销 `crankPinPhys` 走 `worldToDesign`（X 100 / Y 113.2）→ 销钉轨道是长短轴比 1.132 的椭圆；
阻尼槽更明显：宽 `× sceneScale.scale`、高 `|bottom.py − top.py|`（用 scaleY），**同一个矩形用了两把尺**。
实测「销钉到轮心距离 / 轮半径」在改前随转角在 0.187~0.199 之间波动，改后恒为 **0.1808（波动 0.0000）**。
修法：`anchor: 'design'` —— 物理层注释本就写着「1 m = 100 design units」，4.2/6.5 正是按 100 定的，
改锚点后 `scaleX === scaleY === 100`，全部回到作者设定的尺度。
影响面：内容整体上移约 45 px 并纵向缩短 11.6%（原容器比 preset 高 86 px），无裁切；
`maxVectorLength` 两分支均为 `min(420,650..736)×0.3 = 126`，箭头长度不变。
**量级说明**：默认工况偏心距 e ≈ 0.05 m，椭圆造成的绝对漂移仅 ±0.65 px，
所以这是「一致性修复」而不是肉眼可见的错位；但 e = F0/k 随参数变大时漂移会同步放大。
