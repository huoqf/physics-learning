## 一、图表物理坐标拖拽：从页面手写换算改为图表内聚

### 诊断

`useCentripetalPhysics.ts` 里同时存在三份「鼠标 X → 物理量」的等价实现：`waveCardPadding`
常量、`cardRectRef` 量出来的卡片矩形、以及 `handleContainerMouseMove` 里的手写比例换算。
三者的几何基准各不相同（卡片矩形 ≠ SVG 视口 ≠ 绘图区），只靠 padding 常数去逼近，
一旦 `BasePhysicsChart` 的 `margin` 因刻度标签宽度变化而自适应（`autoLeft`/`autoRight`），
点击位置就会整体偏移。

### 方案：把换算下沉到唯一知道绘图区几何的地方

新增 `src/components/Chart/pointerXToPhysX.ts`（纯函数）：

```
userX = offsetX · (viewWidth / rectWidth)      // CSS px → SVG user unit
frac  = (userX − plotLeft) / plotWidth         // 绘图区内归一化位置
physX = lo + frac · (hi − lo)                  // → 物理量，并钳到 domain
```

`inside` 单独返回（`frac ∈ [0,1]`），让调用方决定「点在左侧刻度区」时是否忽略，
而不是用一个假的物理值把非法点击伪装成合法拖拽。

`BasePhysicsChart` 新增三个可选回调 `onScrubX / onScrubStart / onScrubEnd`：
- 只用 `svg.getBoundingClientRect()` + 自己的 `margin.left` + `plotW` + `xDomain`；
- `setPointerCapture` / `releasePointerCapture` 全部包 try/catch（拖拽期间组件重挂载会抛
  `InvalidPointerId`，不包就是控制台错误）；
- `onScrubX` 未提供时不绑定任何指针事件、不加 `cursor: ew-resize` / `touchAction: none`，
  其它 120 多个图表行为零变化。

`RelationChart` 只做转发。`useCentripetalPhysics.ts` 删掉 `waveCardPadding`、`cardInnerPad`、
`cardInnerW`、`cardRectRef`、`isDraggingRef`、`handleDragTime`、`handleContainerMouseMove/Up`、
`handleChartMouseDown`，改为一行映射：

```
v = fitMode === 1 ? r·√x : √(x·r)      // x = 图表横轴物理量（角速度² 或 v²）
```

### 实测（真实鼠标事件，非 DOM 赋值）

| 位置 | 25% | 50% | 60% | 75% | 100% |
|---|---|---|---|---|---|
| 模式 A 得到 v | 5 | 7 | 8 | 8.5 | 10 |
| 模式 B 得到 v | 5 | 7 | — | — | 10 |

按住从 20% 拖到 80% → v = 9（连续更新，无跳变）；点在左侧刻度区被正确忽略（`inside=false`）。

### 附带：模式 A 标题截断

`动力学联动 (F_c = m · a_c)  m=2kg` 实测 `getComputedTextLength() = 74.9px`，
而绘图区右边界在 252.6px 之前就被图例占用 → 改为 `动力学联动  m = 2 kg`。
公式 `F_c = m·a_c` 在右侧物理面板已给出，标题里重复只会挤占空间。

## 二、取消「有效基准下的 14px 硬下限」

### 诊断：14px 下限是一个物理错误制造机

旧实现（`vectorLength.ts`）：

```
len = max(14, min(mag/ref, 1) · maxLength · weight)
```

两个后果：

1. **把 [0, 14] 整段量值压成同一个长度**，映射不再单调；
2. **浮点残差级别的量值被画成实心箭头**。斜抛到最高点时 `v_y` 只剩 1e-16 量级，
   却被画成 14px —— 与 `v_x` 同量级的箭头，画面上直接是「最高点竖直速度不为零」的
   错误结论。

实测（`anim-oblique-throw`，v₀=20、θ=45°、最高点 t≈1.44s）：

| 时刻 | v_y 读数 | 修改前箭头长度 | 修改后箭头长度 |
|---|---|---|---|
| t=1.40 | 0.4 m/s | 14 px | 2.06 px |
| t=1.43 | 0.06 m/s | 14 px | 0.62 px |
| t=1.44 | −0.0 m/s | 14 px | 0.15 px |

### 方案

`calculateVectorPixelLength` 只在**两种退化情形**保留 `minLength`：
`refMagnitude <= 0`（配置错误，附 `console.warn`）与 `mag <= 0`（零/负量值，
`VectorArrow` 本身不渲染，但另有若干调用方拿返回值做标签定位，需要非零占位）。
有效基准下返回纯比例值，不再兜底。

### 小箭头必须连「箭头几何」一起缩

只取消长度下限会带来两类新病：7px 的三角头 + 3px 的线宽套在 4px 的箭头上，
箭头退化成一坨看不出方向的色块。新增 `src/utils/arrowGeometry.ts`：

```
headLen   = min(16, max(total·0.28, min(3, total)))
stroke    = override ?? max(min(3, total·0.09), total·0.04)
headWidth = max(headLen·0.6, min(stroke·1.4, headLen·1.2))
```

三条约束各有实测来由：

| 约束 | 来由 |
|---|---|
| `headLen` 下限 3 且不超过 `total` | 三角尖低于 3px 不可辨；若头部超过总长，三角底边会跑到起点背后，方向被反向画出 |
| 线宽 `min(3, total·0.09)` | 与旧公式在 total ≈ 33.3px 处连续 → **常规尺寸视觉零变化** |
| `headWidth ≥ stroke·1.4` | 分量箭头统一 `strokeWidth={2}`：10px 箭头若按 `0.6·headLen` 只有 1.8px 宽，比线还窄，圆头线段无方向 |
| `headWidth ≤ headLen·1.2` | 上面那条在亚像素箭头会把 0.6px 的三角撑到 2.8px 宽 —— 竖直矢量变成一条横向细线，方向直接读反 |

实测（`anim-oblique-throw`）：

| 情形 | 箭头总长 | 头长 | 头宽 | 线宽 | 结论 |
|---|---|---|---|---|---|
| v_y 常规 | 68.9 | 16.0 | 9.6 | 2 | 与旧实现逐位相同 |
| v_y = 2.3 m/s | 9.70 | 3.0 | 2.8 | 2 | 短箭头仍是可读的三棱状 |
| v_y = 0.06 m/s | 0.62 | 0.62 | 0.75 | — | 亚像素点，无横向细线 |

## 四、遗留观察（未在本次修改）

### 1. `refMagnitudes` 缺失 → 仍是恒定 14px 箭头（同一类错误未清完）

扫查中仍有页面在 `console.warn`：

| 页面 | 缺失类型 |
|---|---|
| `anim-clapeyron` | force |
| `anim-cutting-emf` | force |
| `anim-forced-resonance` | tension |
| `anim-gas-laws` | force |
| `anim-kepler` | velocity / gravity |
| `anim-light-rod-rope` | gravity |
| `anim-lorentz-force` | lorentzForce |
| `anim-nuclear-decay` | force |
| 另有多页 | force / appliedForce / normalForce / friction |

这些页面的箭头**不随量值变化**（永远 14px），与本次修掉的病同源，但根因是场景没配基准，
不是公式问题。修法只有一条：逐页补 `refMagnitudes`（或改为按峰值动态计算）。
建议单开一批处理，不要混进本次改动。

### 2. 取消下限后缩到 3–10px 的箭头（说明这些页的基准偏大 2–4 倍）

默认帧实测（`总长 min`，旧值均为 14）：

`circular-motion` 3.1、`light-rod-rope` 4.9、`sensors` 5.0、`induction-single-rod` 5.6、
`vertical-spring` 6.0、`self-induction-eddy` 6.4、`impulse-concept` 6.8、`em-wave` 6.9、
`block-board` 7.5、`experiment-resistivity` 7.9、`simple-pendulum` 9.5、`newton-second` 9.6、
`kinematics-advanced` 13.5。

这些不是公式病，是基准病：`ref` 取到峰值 2–4 倍时，典型量值必然只有几像素。
现在至少是**比例正确**的小箭头（能看到方向、能比较大小），比过去「全等长」更真实；
若要恢复可读性，应调小对应场景的 `refMagnitudes`。建议与第 1 条合并成「矢量基准审计」批次。
