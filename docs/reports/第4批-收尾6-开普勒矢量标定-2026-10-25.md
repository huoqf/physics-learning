# 第4批·收尾6 — 开普勒矢量标定（几何尺 vs 画布尺）

> 日期：2026-10-25
> 范围：`anim-kepler`（开普勒定律）单页。
> 结果：**峰值速度箭头 198.9 → 77.8 px（= 0.54 × 半长轴），引力箭头 139.2 → 20.7 px（箭尖停在日面外 2 px）**；
> 两者对窗口尺寸与 `a₁` 滑杆都不再漂移。

---

## 一、现象

用户反馈「开普勒运动矢量视觉上有点太大」。实测（1440×900，默认 a=4.5 / b=3.0）：

| 量 | 改前 |
|---|---|
| 轨道椭圆 | rx=144、ry=96（`scaleBase=32` design-unit/m 固定，2a=288、2b=192 px） |
| v 箭头（近日点峰值） | 198.9 px |
| F 箭头（近日点峰值） | 139.2 px |
| v / 半长轴 | **1.38**（比半长轴还长 38%） |
| v / 半短轴 | **2.07** |
| 近日点行星—太阳距离 | `r_min=1.15 m × 32` = 36.7 px |
| F 箭头 / 日—行距离 | **3.4**（箭头穿过太阳画到其左侧） |

即：v 箭头比椭圆整个竖直高度（192 px）还长，F 箭头直接捅穿太阳并压住 `r₁` 标签。

## 二、根因：两把尺

1. **触发**：收尾 3 把本页 `refMagnitudes` 从「未配置」改成 `refFromPeak(峰值)`。
   改前 `ref=0` → `calculateVectorPixelLength` 退化成 `minLength` 常量 14 px（外加逐帧告警），
   所以箭头"变大"是那一批造成的——方向正确（以前箭头完全不随速度变化），但标定到了错的尺子上。
2. **结构**：`峰值箭头 = 0.9 × maxVectorLength × weight`，而本页没传 `maxVectorLength`，
   默认取 `0.3 × 可视区短边 = 220.8`（**画布尺**）；本页几何却由 `physicsScaleDesign = 32`
   这个常量固定（**世界尺**）。两把尺互不相干，于是：

   - 峰值箭头恒为 198.7 px，**与轨道大小无关**：a₁ 2.5 → 5.5，半长轴 80 → 176 px，比值 2.48 → 1.13；
   - 换窗口还会漂：1440×900 = 198.9、1920×1200 = 177.9、1100×760 = 175.5，同一时刻轨道恒为 288×192。

   对照其余 center 锚点页（匀速圆周 87.8、竖直圆周 139.3、双星 40/50、单摆 68.6），
   换窗口一个数都不变——它们的 `physicsScaleDesign` 都由 preset 推出，几何与上限同一把尺。
   **全库只有本页**给 `physicsScaleDesign` 传了字面常量且未显式给 `maxVectorLength`。

## 三、改动（`KeplerAnimation.tsx` 单文件）

```ts
// 1) 矢量上限与轨道同尺：0.6 × 半长轴像素
const maxVectorLength = KEPLER_CONFIG.scaleBase * a1 * 0.6

// 2) 引力箭头按几何距离封顶：箭尖必须停在太阳本体之外
const rMinPx = rMin * KEPLER_CONFIG.scaleBase
const gravityPeakPx = Math.max(6, Math.min(0.75 * rMinPx, rMinPx - SUN_CORE_R - 2))
const gravityFill = Math.min(1, gravityPeakPx / (maxVectorLength * VECTOR_VISUAL_WEIGHT.gravity))
// refMagnitudes.gravity = 峰值 / gravityFill
```

- 太阳图元半径抽出模块常量 `SUN_GLOW_R = 28` / `SUN_CORE_R = 14`，绘制与箭头封顶共用，避免两处各写一个 14。
- 顺带修正：**F 的标签改到箭尾（行星一侧）**。默认锚点是「箭尖外 10 px」，而近日点箭尖本就贴在日面外 2 px，
  标签必然落进太阳本体，读起来像在给太阳贴 `F`（太阳自己的标签是 `F₁`，语义冲突）。
- 为什么不用固定的 45%：`e≈0.745` 时 45% 也等于 27 px，箭尖落在距日心 9 px 处，直接埋进 14 px 的日面里；
  而几何封顶在极端参数（a₁=5.5 / b₁=1.5 → e≈0.96）下会自动收缩，固定百分比则会戳穿太阳。

### 3.1 同批收掉的标签压字：模式 1 的「近日面积 S₁」×「太阳 (焦点 F₁)」

`近日面积 S₁` 画在 `(originX + a1·scaleX − 25, originY + b1·scaleX·0.32)` = **(539, 356)**；
`太阳 (焦点 F₁)` 原先画在 `(sunDx − 11, sunDy + 32)` = **(516, 357)** 且左对齐 —— 文字从 516 一路铺到约 600，
两串正好同高度叠在一起，放大后是糊成一片的红黑字。

修法：太阳标题改成**右对齐、落在太阳左侧**（`x = sunDx − 32, textAnchor="end"`，占 407 ~ 495）。
选它而不是挪 S₁ 的原因：近日点一侧已被日面光晕（半径 28）、行星（半径 10，距日心 36.7 px）、
v/F 箭头与「行星」标注占满，`S₁` 没有第二处可去；而椭圆左半是空的，太阳标题移到左侧零挤压。
模式 0 的 `副焦点 F₂`（313, 325）与 `r₂` 标注（413, 317）分别与它相距 60 px / 40 px，不冲突。

## 四、实测（改后）

| 场景 | v | F | v / 半长轴 | F 箭尖到日心 |
|---|---|---|---|---|
| 1440×900 | 77.8 | 20.7 | 0.540 | 16.0 px（> 14，日面外 2 px） |
| 1920×1200 | 77.8 | 20.7 | 0.540 | 16.0 px |
| 1280×800 | 77.8 | 20.7 | 0.540 | 16.0 px |
| 1100×760 | 77.8 | 20.7 | 0.540 | 16.0 px |
| a₁=2.5（rx=80） | 43.2 | 6.0 | 0.540 | 10.0 px |
| a₁=5.5（rx=176） | 95.0 | 12.5 | 0.540 | 16.0 px |

- **窗口无关**：四个尺寸同一帧取到完全相同的 77.8 / 20.7。
- **a₁ 无关**：比值恒 0.540（改前 1.13 ~ 2.48 乱跳）。
- **全周期采样**（55 帧，T=10 s）：v 11.3 → 77.8 px；F 3.0 → 20.7 px（更短的采样点已无箭杆，未计入）。

## 六、遗留（均非本次改动引入，待定）

1. **参数域允许把近日点拖进太阳**：a₁=2.5 / b₁=1.5 时 `r_min = 16 px`，而日面半径 14 px、行星半径 10 px，
   行星本身已压在日面上。此时"箭头不进日面"无解，故对 F 的长度设了 6 px 下限（否则箭头塌成 0，等同矢量消失）。
   根本解法是限制 `b₁ ≤ 0.85·a₁` 或缩小太阳/行星图元，需要产品层面拍板。
2. **远日点 F 亚像素**：`e=0.745` 时引力量程 47 倍，线性映射只能保一头。现在保住的是近日点；
   若希望远日点也可见，只能给 F 单独用 `pixelLength` 恒定长度（卫星页即此做法，注释写明"方向标注"）。
