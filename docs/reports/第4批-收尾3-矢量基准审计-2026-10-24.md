# 第4批·收尾 3 —— 矢量基准（refMagnitudes）全量审计

日期：2026-10-24
范围：`src/utils/vectorRefs.ts`（新增 `peakOverRays`）、`src/utils/vectorLength.ts`（移除临时探针），
以及 13 个动画页面的场景基准配置。

承接《第4批·收尾 2》遗留的两条观察：① 部分页面 `refMagnitudes` 缺失 → 箭头退化为恒定 14px 并刷
`console.warn`；② 部分页面基准偏大 2~4 倍 → 箭头缩到 3~10px。两者同源，合并为一批处理。

---

## 一、先把「事实」测出来：124 页运行时探针

静态扫源码判断「谁缺基准」是不可靠的：一个组件文件常被多个 `anim-*` id 复用，静态分析的 29 个
「缺失页」里有大量误报。改为在 `calculateVectorPixelLength` 内临时埋点（本批结束时已删除），
用 Playwright 逐页真实加载 124 个动画页，记录每个（页面, 矢量类型）的**实际传入量值最大值**、
当前基准与 `maxVectorLength`：

```
len = min(max / ref, 1) · maxLen · weight[type]
```

实测结论（默认帧，修改前）：

| 类别 | 页面数 | 类型槽位 | 表现 |
|---|---|---|---|
| `ref = 0`（基准缺失） | 5 | 10 | 全部退回 `minLength` = 14px，长度与量值无关 |
| 基准偏大 | 4 | 5 | 默认帧 0.8 ~ 9.5px（亚像素到一条线） |
| 载荷是单位向量 | 1 | 2 | 长度由假基准决定，且**量值越大箭越短** |
| 无问题 | 114 | — | — |

修改后同一次扫描（124 页）：**`refMagnitude` 告警 0 条**；全量 104 条（页面, 类型）记录中，
`len < 12px` 的只剩 6 条 —— 其中 3 条是 `max = 0`（该帧本来就没画箭头），另外 2 条是**物理上本该如此**
（见第四节）。

## 二、校准策略：四种情形，四条规则

`ref` 的语义只有一个：**让「量值峰值」落在 `0.9 · maxLen · weight` 上**（`REF_PEAK_FILL = 0.9`，
留 10% 余量避免 `min(ratio,1)` 把不同幅值压成同一长度）。剩下的问题是「峰值取哪一段」：

| 情形 | 规则 | 本批页面 |
|---|---|---|
| 量值随时间变化（轨道、振动、往复） | 取**当前参数下整个运动过程的峰值**（复用页面自己的物理函数采样） | Kepler、ForcedResonance、NuclearDecay |
| 量值不随时间变化，由滑杆驱动 | 取**单滑杆极值扫描**峰值（`peakOverRays`） | CuttingEMF、LorentzForce、SystemIsolated、NewtonSecond、CircularMotion、ImpulseConcept |
| 量值本就是世界坐标长度 | `refFromWorldUnit`（箭头像素长度 = 世界长度 × scale） | Clapeyron、GasLaws |
| 箭头只表示方向 | 显式 `pixelLength` + `arrowType`，不给假的 `ref` | Satellite、SecondLaw |

### 为什么新增 `peakOverRays`（单滑杆极值扫描）

「按参数最大量程」字面上有两种极端取法，都会踩坑：

1. **全滑杆同时取端点（角点）**：`cutting-emf` 的 `F_安 = B²L²v/R` 在 `B=3, L=2, v=5, R=0.5` 时是
   默认帧（2.25 N）的 **160 倍**。据此反推 `ref`，默认帧的箭头变成 0.6px 的亚像素点。
2. **取当前参数的量值**：量值恒定、基准跟着当前值放大 → `ratio ≡ 0.5`，箭头长度**永远不变**。
   改滑杆时看不到力的变化 —— 正是本批要清掉的病。

单滑杆扫描（默认值出发，每次只把一个滑杆推到量程一端，取所有采样最大值）对应学生真实的操作方式：
峰值与默认帧同量级、默认帧可读，任一滑杆全程移动时箭头仍能长到接近满量程。实现：

```ts
peakOverRays(evaluate, base, { v: [-5, 5], B: [-3, 3] })   // evaluate 必须复用页面自己的物理函数
```

新增 6 个单测（含 `cutting-emf` 同构的 `B²L²v/R` 案例：扫描 9 N vs 角点 360 N）。

## 三、逐页修改

### 3.1 基准缺失（原本恒定 14px）

| 页面 | 类型 | 修改前 | 修改后 ref | 默认帧长度 |
|---|---|---|---|---|
| `cutting-emf` | appliedForce | ref=0 → 14px | 6.25 N | 24.6px |
| `cutting-emf` | lorentzForce | ref=0 → 14px | 6.25 N | 21.1px |
| `lorentz-force` | lorentzForce | ref=0 → 14px | 44.4 N | 28.5px |
| `system-isolated` | appliedForce / gravity / normalForce / friction | ref=0 → 14px | 共用 152.4 N | 14.5 / 56.9 / 48.8 / 7.3px |
| `satellite` | gravity / velocity | ref=0 → 14px | `pixelLength` 26 / 34 | 方向标注 |
| `second-law` | velocity | ref=0 → 14px（靠 `120/scaleX` 伪装成 120px） | `pixelLength` 120 | 方向标注 |
| `light-rod-rope` | gravity | ref=0 → 14px（`IDENTITY_SCENE_SCALE`，`maxVectorLength = 1`） | `pixelLength` = `m·g·5` | 恢复原设计长度 |

`cutting-emf` 只拿**切割速度**这一条滑杆做扫描轴：`B`、`L` 各带平方，四条滑杆一起扫仍有 16 倍；
`v` 是本页主教学变量。`system-isolated` / `newton-second` 的四~五个力**共用同一基准**，理由见 3.3。

### 3.2 基准偏大（原本 0.8 ~ 9.5px）

| 页面 | 类型 | 修改前 ref | 修改前长度 | 修改后 ref | 修改后长度 |
|---|---|---|---|---|---|
| `circular-motion` | acceleration | 250（图表纵轴量程） | 3.1px | 11.1 | 70.2px |
| `circular-motion` | velocity | 50（图表纵轴量程） | 19.5px | 11.1 | 87.8px |
| `impulse-concept` | appliedForce | 200 | 6.8px | 22.2 | 61.4px |
| `intermolecular-forces` | force | 0.75（含 `max(…,0.5)` 下限） | 0.8px | 0.0117（本帧归一化） | 52.7px |

- `circular-motion` 把**图表纵轴的量程**（`aMax = r_max·ω_max² = 250`）当成了箭头基准。`a_c ∝ ω²`
  使角点是默认帧的 50 倍。改为按半径滑杆扫描（10 → `ref` 11.1），ω 到 2 倍时撞满量程截断，
  ω² 关系由右侧曲线承担。
- `intermolecular-forces` 的 `F_斥 = 1/r¹³`、`F_引 = 1/r⁷` 在 `r ∈ [0.5,4]` 内跨 5 个数量级，
  固定线性基准无解，保留「本帧归一化」；真正的缺陷是 `max(…, 0.5)` 下限 —— r 稍大时三个力都远小于
  0.5，基准被下限撑住，箭头缩成 0.8px。改为只保留防 0 的 `1e-12`。

### 3.3 新发现的缺陷（不在原报告清单里）

| 缺陷 | 页面 | 说明 | 处理 |
|---|---|---|---|
| **单位向量载荷** | `newton-second` | 速度/加速度箭头传 `vector={{x:1,y:0}}`，长度由 `ref = max(值,5)*2` 决定 → 长度恒为 0.5 满量程，且**速度越大箭反而越短**（ref 跟着涨） | 改传真实 `{x: v}` / `{x: a}`，基准固定 |
| **动态基准使同类力失去可比性** | `newton-second` | 每个力的 ref 各取 `当前值×2` → 同一帧里 `F_外` 与 `f` 永远等长；把 F 从 10 N 拖到 50 N 箭头一动不动 | 五个力共用一把尺（`ref` = F 量程上界），并删除 `dynamicRefMagnitudes` |
| **跨类型长度反转** | `system-isolated` | 若每个力按自己的量程定基准（F→30 N、G→137 N），`F=15 N` 的箭（60px）比 `G=58.8 N` 的箭（51px）更长 —— 画面直接说反话 | 四种力共用 `ref` = 重力峰值 |
| **两种模式量纲不一致** | `satellite` | mode 0 传 `{−y, x}`（长度 ∝ r）、mode 1 传单位向量 `velocityDir`，一份 `ref` 无法同时成立 | 明确为方向标注（`pixelLength`） |
| **registry sceneLayout 覆盖后基准为空** | `newton-second` | 注册表的 `sceneLayout` 只声明画布尺寸，`contextProfile.refMagnitudes` 为空对象，本地基准被整体顶掉 → 全部退回 14px | 本地基准与注册表基准做并集 |

## 四、两处「看着小、其实对」的页面（未改）

`len < 12px` 的 6 条记录里，有 2 条是物理结论正确的结果：

| 页面 | 类型 | 长度 | 为什么不该放大 |
|---|---|---|---|
| `simple-pendulum` | appliedForce（F_回） | 9.5px | `F_回 = G·sinθ`，小角 θ₀=8° 时本来就只有重力的 14%。它与重力箭头**共用同一基准**，9.5px/68.7px = 0.139 = sinθ —— 长度比本身就是知识点 |
| `system-isolated` | friction | 7.3px | `f = 8.82 N` 相对 `G = 58.8 N` 是 1:6.7，同一把尺下就该这么短 |

`kinematics-advanced` 的 `velocity`（ref 24 = `|v₀|+|a|·10`，即「10 秒加速度窗」）同样保留：
默认帧 t=0 时 v=4 → 13.5px，随播放时间增长到满量程，属于「时间轴驱动的量值」。

## 六、遗留

1. **非等比缩放告警（另一类告警，未在本批范围）**：`system-isolated`（70 vs 40.6）、`second-law`
   （84 vs 83.98）、`newton-second`（1 vs 1.08）仍会打印 `[VectorArrow] sceneScale 非等比缩放`。
   这是 `anchor:'viewport'` + `physicsWidth/Height` 与可视区宽高比不匹配造成的，与本批的
   `refMagnitudes` 无关，需要单独一批处理（要么修正 `physicsWidth/Height`，要么显式声明
   `intentionalNonUniformScale`）。
2. **`system-isolated` 的 F 箭标签碰撞**：F 箭按正确标度只有 14.5px，`VectorArrow` 的标签固定放在
   箭尖 +10px 处，落进了 m₂ 方块内。属标签定位逻辑的固有问题（与 `glow`、`glowOffset` 无关联的一次性
   定位），未在本批处理。
3. **`system-isolated` 面板在 t=0 时把「系统加速度 a」显示为 0.00 m/s²**：右侧量值表用
   `time > 0 ? acceleration : 0` 门控显示，而 `F=15 N > f_合=8.8 N` 时该系统的加速度恒为
   1.03 m/s²（t>0 后面板即显示 1.03）。属既有的「未开始播放就先显示 0」展示约定，
   不是计算错误，未在本批改动。
4. `lorentz-force` 的**进阶模式（速度选择器）**粒子受力由 canvas 直接绘制，不走 `VectorArrow`，
   因此不参与本套基准；其长度标度尚未审计。
