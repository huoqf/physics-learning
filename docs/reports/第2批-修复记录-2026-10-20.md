## 二、验证中暴露并修掉的问题

### 2.1 斜抛看板仍是"平抛专属结论"（B2-2 的同类残留）

`quantities/kinematics/obliqueThrow.ts` 有三处同样的概念错误，提示条只是其中一处：

- 物理量「速度/位移偏角正切比」显示 `tanθ/tanα`。t=0 时位移角未定义（0/0），被兜底成抛射角后**恒显示 1.00**，而旁边标注的是 `2tanα`——自相矛盾。
- 公式「速度偏角与位移偏角定理」写 `tanθ = 2tanα`，条件赫然标着"斜抛/平抛通用大杀器"。
- 高考要点「偏角中点定理」写成"在无阻力斜抛/平抛中…恒等于 2 倍"。

**改法**：不再展示那个比值，改为直接给出恒等关系残差 `tanθ + tanθ₀ − 2tanα`，无阻力时恒为 0，学生可在任意时刻暂停自证；t=0 明确显示"位移偏角尚未定义"。公式与高考要点同步改为 `tanθ = 2tanα − tanθ₀`。

**验证**：t=0 → `t = 0，位移偏角尚未定义`；t=1.443s（最高点，tanθ=0、tanα=0.5、tanθ₀=1）→ `残差 0.00` ✅

> 说明：`quantities/kinematics/projectile.ts` 与 `ProjectileScene.tsx` 里的 `tanθ = 2tanα` 只服务 `anim-projectile`（纯平抛），结论正确，未动。

### 2.2 追及相遇读数三角形不闭合

`calculatePoliceChase` 返回的 `xA = vA·t` 是**相对轿车自身起点**的位移，而路面图与 x-t 图都把轿车放在 `Δx₀ + xA`。读数直接印 `state.xA`，于是 t=0 时出现：

```
x_A = 0.0 m    x_B = 0.0 m    Δx = 80.0 m      ← 0 − 0 ≠ 80
```

**改法**：新增 `dispXA = chaseMode === 0 ? Δx₀ + state.xA : state.xA`，与图表、路面共用同一套绝对位置。不新增概念，只是让 `x_A − x_B = Δx` 重新成立——这本身就是可让学生自查的一致性。

**验证**：t=0 → `x_A=80.0 / x_B=0.0 / Δx=80.0`；t=10s → `x_A=430.0`（=80+35×10）、`x_B=226.7`、`Δx=203.3`，逐项对得上 ✅

## 三、确认但本轮不动的缺陷

**右屏首帧兜底面板会串域贴错标签。**

`physicsQuantities.ts` 的 `COMMON_PARAM_LABELS` 是"裸英文键 → 中文名"的**全局**映射，只按 key 查，不看动画。于是：

- 板块模型的木板长度 `L`（2.50 m）显示为 **"电感 L"**
- 远距离输电的变压器变比 `k`（0.02）显示为 **"劲度系数 k"**
- 未收录的 key 仍然裸奔：`mu1`、`angle`、`advancedMode`、`deltaT`、`modelIdx`…

这不是首帧闪烁那么简单，是**又一处双真源**：注册表 `paramMeta` 里明明写着每个控件的中文标签与单位，兜底面板却自己另造了一份。正确做法是让兜底函数接收该动画的 `paramMeta` 并按 key 取标签，全局映射表应当删除。

涉及函数签名变更（`buildFallbackPanel` 需要多一个参数），且会影响全部 124 个动画的首帧渲染，建议单列一项、经确认后再动，不塞进本批。

## 四、顺手处理：首帧兜底面板不刷新

第 1 批记录里挂着的"看板首帧兜底不刷新"，本批一并处理：

- `physicsQuantities.ts` 的 `preloadQuantityBuilder` 把 `reg.loader()` 直接抛在 `.then()` 里，任一构建器加载失败或与首帧渲染抢跑，`Promise` 就永远不 resolve，页面便**永久**停在英文参数名上。
- `AnimationPage.tsx` 用 `.then()` 置 ready 标志，同上——rejected 时标志永远翻不过来。

改为 `try/catch` 包住 loader 并 `console.warn` 后返回，`AnimationPage` 改用 `.finally()`，保证无论成功失败标志都会翻。

**实测澄清（避免误记为逻辑缺陷）**：本批验证初期，斜抛页首次进入 2.5 s 后仍停在 `angle / advancedMode / viewMode…`，一度以为是竞态未消。逐帧打点后结论相反——

- 冷启动（该 `quantities` 分包首次被请求，Vite 需按需转译整个模块图）：可达数秒，期间持续显示兜底列表；
- 热态（同一路由再来一次）：**155 ms 就绪，兜底列表一帧都没出现**。

所以这是 dev server 的按需转译延迟，不是渲染竞态。`.finally()` 与 `try/catch` 仍然是必要的安全网（构建器真失败时不会永久卡住），但不该算作"修好了一个 bug"。
