## ①  capacitors：RC 充放电暂态

### 模型层（单一真源）

```ts
computeRCTransient(emf, R, C, t, phase) → { tau, uC, i, q, progress, areaCharge, storedEnergy, heatPower }
rcTauFromParams(params)   // kΩ × μF → s（1 kΩ·μF = 1 ms）
```

### 实测（默认 E=6 V、R=10 kΩ、C=200 μF ⇒ τ=2.00 s）

| 时刻 | u_C | i | q | ∫i dt | E_C | P_热 |
|------|-----|---|----|-------|-----|------|
| 充电 t=0 | 0.00 V | 0.600 mA | 0.0 μC | 0.0 μC | 0.00 mJ | 3.60 mW |
| 充电 t=τ | 3.79 V (63.2%) | 0.221 mA | 758.54 μC | 758.54 μC | 1.44 mJ | 0.49 mW |
| 放电 t=0 | 6.00 V | 0.600 mA | 1200.00 μC | 0.0 μC | 3.60 mJ | 3.60 mW |
| 放电 t=2.5 s | 1.72 V | 0.172 mA | 343.81 μC | 856.19 μC | 0.30 mJ | 0.30 mW |

充电时「面积 = q」，放电时「面积 = CE − q」（343.81 + 856.19 = 1200.00）—— 两条都自洽。

### 现场发现并修掉的 3 个缺陷

1. **`u_C` 标注被数据卡压住**：标注原本写在电容右边（`capX + 62`），正好落在数据卡
   （`cardX = W - 220`）下面，实际渲染只剩半个字。改为写在回路内侧、右对齐。
2. **电容画成左右两块竖板**：右支路是竖直导线，两块竖板的缝隙正好对着导线落点，
   等于把极板短接，物理图形是错的。改成「上下两块水平极板 + 极板间隙」，
   导线接在上极板上方、下极板下方。这条只有真跑页面看截图才会发现，读代码看不出来。
3. **放电时面积公式与 q 混读**：原来无条件写 `∫i dt = ΔQ = C·u_C`，放电模式下
   面积 758 μC 而 q 只有 441 μC，学生必然对不上。改为按充/放电分别给出
   `∫i dt = C·u_C` 与 `∫|i| dt = CE − C·u_C`，并在条件栏注明「已放出的电量」。

## ② 平抛运动：频闪打点图层

### 模型层

新增 `src/physics/projectileStrobe.ts`：

```ts
computeProjectileStrobe(v0x, g, period, uptoT)
  → { period, marks[{k,t,x,y,dyPrev}], dx, firstDy, diffOfDy, ratios }
```

三个可测量一次给全：水平间距 `Δx = v₀T`、竖直间距成 `1:3:5`、逐差 `ΔΔy = gT²`。
`1e-9` 容差保证「接地瞬间恰好是 T 的整数倍」时不漏最后一帧。

### 界面层

- `ProjectileStrobeLayer.tsx`：打点空心圆（不遮轨迹）、前 3 段竖直间距的测量括号与读数、
  画布左下角三行结论注释。
- `ProjectileScene` 新增 `v0x / g / strobeMode / strobeT / airResistance` 五个入参，
  在轨迹之后、小球之前插入图层。
- 注册表：`showIf: strobeMode` 的「频闪周期 T」参数（0.05–0.5 s，推荐 0.2），
  外加一条「📷 频闪照片」教学提示。
- 看板新增：频闪周期 T / 已打点数 n / Δx = v₀T / Δy₁ / 逐差 gT² / 竖直间距比，
  以及三条公式（Δx = v₀T、Δy_k = ½gT²(2k−1)、g = ΔΔy/T²）与一条高考点。

**有空气阻力时整层关闭**：`airResistance > 0` 时竖直方向不再是 ½gt²，`Δy = gT²` 不成立。
此时看板显示「频闪打点：已关闭」并给出一条前提说明，而不是继续输出错误结论。

### 实测（v₀=10 m/s、g=9.8、T=0.2 s、t=1.0 s）

- 已打点数 n = 6（0, 0.2, …, 1.0）
- 水平间距 Δx = 2.00 m（每段都是 2.00 m）
- 首段 Δy₁ = 0.196 m，括号实测 0.20 / 0.59 / 0.98 ⇒ 1 : 3 : 5
- 逐差 ΔΔy = gT² = 0.392 m

## ③ `anim-centripetal`：F–ω² 实验探究（原地升级右上角卡片）

### 架构遵守

圆周场景是旋转对称的，必须留在 `CANVAS_PRESETS.square` —— 换成 splitV / splitH 会把圆形轨道
拉成椭圆。所以本次**不动任何容器与 Preset**，只把右上角已有的 `RelationChart` 卡片
换成「模式 A / 模式 B」两种渲染，卡片尺寸、位置、拖动逻辑全部沿用。

### 模型层

新增 `src/physics/centripetalFit.ts`（仓库里没有 `circular.ts`，`circularModels.ts` 已占
`circular*` 前缀，故用 `centripetalFit` 避免歧义）：

```ts
computeCentripetalFit(m, r, { vMin, vMax })
  → { slope, fitSlope, slopeError, samples[5], omegaSqMax, compareSlope, fMax }
sampleFitLine(fit, n)
```

- `slope = m·r`（理论结论）；
- 5 组采样点按 v 在 [1,10] 均匀取，`ω² = (v/r)²`，测量值叠加**固定残差序列**
  `[+1.0%, −1.2%, +1.4%, −0.6%, +0.8%]`（不用随机数，保证每次渲染/每条测试完全一致）；
- `fitSlope` 由这些点做**过原点最小二乘** `k = Σ(ω²·F)/Σ(ω²²)` 得到 —— 不是把 `m·r` 抄一遍，
  否则「拟合」二字就没有意义；
- `omegaSqMax = (vMax/r)²`：横轴上限取当前半径下**真正可控**的 ω² 范围，
  而不是一个与 r 无关的常数。

### 界面层

- 注册表新增 `fitMode` 分段（理论 F–a / 实验探究 F–ω²）与 `showCompare` 开关
  （质量加倍 → 斜率翻倍），并配两条随模式切换的教学提示。
- 卡片：模式 A 原样保留；模式 B 主曲线是拟合直线，`markers` 画 5 个采样点，
  淡虚线叠一条理论线（`k = m·r`），可选再叠一条 `2m` 对照线。
- 看板：ω²、理论斜率 `m·r`、拟合斜率 `k_fit`、拟合相对偏差、采样点数，
  开对照时补对照组斜率；公式补 3 条，高考点补「向心力演示仪 / 图线斜率的物理意义」2 条。

### 顺手修掉的既有缺陷：卡片拖动从来没生效过

原来把点击位置换算成横坐标用的是
`(clientX − 容器left − vp.tx) / vp.scale`，等于把卡片当成**画布内**元素。
但卡片是绝对定位的 HTML 元素，宽高直接取设计像素（`cardWidth × cardHeight`），
根本没有跟着 `vp.transform` 缩放。容器宽 ≠ 650 设计宽时，换算结果整体偏移约
290 设计像素，`clickX` 直接超出图区，`if` 判空 —— 拖动在任何常规窗口下都不起作用。

改为在 `mousedown` 时记录卡片自身的 `getBoundingClientRect()`，
点击位置按「卡片左内边距 + 卡片内宽」折算。A/B 两种模式现在都能拖：

| 点击卡片横向位置 | 30% | 50% | 75% | 90% |
|---|---|---|---|---|
| 模式 B（F–ω²）v 结果 | 4.5 | 6.5 | 8.5 | 9.5 |
| 模式 A（F–a）v 结果 | — | 6.5 | — | — |

（模式 B 50% 处理论值 v = r√(ω²max·90/205) ≈ 6.6，读数 6.5 一致；
 偏差来源是图区实际左内边距 36.5 px 与布局常量 40 px 的差，约 4%，属可接受的近似。）

### 实测（默认 r=3、m=1、v=3）

- 理论斜率 k = m·r = 3.00，拟合斜率 3.014，相对偏差 +0.5%
- 对照（质量加倍）斜率 6.00，面板同步显示
- 模式 A 下看板不出现任何「拟合」读数（两套斜率不会同时塞给同一张图）

### 测试

`src/physics/__tests__/centripetalFit.test.ts`（6 条）：斜率 = m·r、采样点满足 ω²=(v/r)²
且残差 <2%、拟合斜率与独立复算的 Σxy/Σx² 一致且**不等于**理论值、采样可复现、
质量/半径加倍斜率翻倍、拟合直线过原点。
`dualSourceGuard` 新增 #13：看板理论斜率/拟合斜率/偏差与 `computeCentripetalFit` 同源，
模式 A 不输出拟合读数。
