# 第 4 批 · 收尾 8：开普勒内外轨共焦与取景修复

日期：2026-10-26　关联：收尾 7（`09a2090`、`20e6fea`）

## 一、触发：外部评审指出「内外轨同心，不共焦」

评审提出：太阳画在内轨右焦点 `c₁ = a₁e₁` 上，而外轨椭圆 B 的圆心留在世界原点 `(0,0)`，
于是 B 的右焦点在 `c₂ = a₂e₂`。当 `c₁ ≠ c₂` 时两条轨道不是共焦椭圆，
**行星 B 会绕着太阳右侧的一段"空气焦点"加减速**，直接违背本页要讲的第一定律。

复核结论：**成立**。代码事实三处：

| 位置 | 内容 |
|---|---|
| `useKeplerPhysics.ts:211` | `sunPhysX = c1` |
| `useKeplerPhysics.ts:247`（改前） | `planetBX = orbitB.x`（以椭圆中心为原点、右焦点在 `+c₂`） |
| `KeplerAnimation.tsx:327`（改前） | 外轨 `<ellipse cx={sceneScale.originX}>` |

**实机实测**（第三定律模式，点"播放"后采样 704 帧，画布 px ÷ 32 还原成世界单位）：

| | 实测 B→太阳 | 共焦应得 | 偏差 |
|---|---|---|---|
| 近日 | 4.125 | 3.000 | +1.125 |
| 远日 | 10.875 | 12.000 | −1.125 |

偏差恰为 `c₂ − c₁ = 4.5 − 3.375 = 1.125`，与"整条外轨右移一个 `c₂−c₁`"的预测分毫不差。

## 二、修法一：共焦平移（渲染层，不动任何读数）

```ts
const orbitBCenterX = c1 - c2          // 外轨椭圆的中心
const planetBX = orbitB.x + orbitBCenterX
```

`evaluateKeplerOrbit` 的 `r / v` 都是相对"自己的右焦点"算的，所以这是**纯平移**：
`r`、`v`、`T`、`k` 一个都不变，看板与双真源守门不受影响。

修复后实测：`外轨 cx − 内轨 cx = −36 px = −1.125`、`太阳到外轨中心 = 4.500 = c₂`、
`B→太阳 = 3.000 … 12.000`。

## 三、修法二：按两轨并集取景（修法一的必配项）

只做平移会顶出画布。共焦后外轨左端伸到 `c₁ − c₂ − a₂`，而可用半宽只有 420 px = 13.125 世界单位。
全参数域（`a₁×e₁×a₂×e₂`，38.9 万组）统计：

- 左越界 **11.5%**（最坏 `a₁=2.5, e₁=0, a₂=10, e₂=0.8` → 左伸 18.0 → 576 px，超出 156 px）
- 右越界 **0.2%**（`a₁=5.5, e₁=0.85, a₂=10, e₂=0` → 470 px）

改为把「两轨并集中点」放到画布中心：

```ts
const left  = mode === 2 ? Math.min(-a1, orbitBCenterX - a2) : -a1
const right = mode === 2 ? Math.max( a1, orbitBCenterX + a2) :  a1
const sceneCenterX = preset.width / 2 - ((left + right) / 2) * KEPLER_CONFIG.scaleBase
// useSceneScale({ centerSource: 'custom', centerX: sceneCenterX, centerY: preset.height / 2 })
```

- 并集最大半宽 **376 px < 420 px** → 任意参数组合都不越界（原点最大平移 248 px）
- 模式 0/1 只有内轨，中点恒为 0 → 与改动前完全等价（实测太阳 x 仍为 528、内轨 cx 仍为 420）
- 极端参数实测（`a₁=2.5, e₁=0, a₂=10, e₂=0.8`）：B 全程 `x 92…731`、`y 133…496`，全部落在 `840×650` 内

## 四、修法三：`ParamControl` 同步 effect 值相等短路 —— **并更正一个误判**

改动（`ParamControl.tsx:119`）：effect 里逐键比对格式化字符串，全部相同就 `return prev`
（相同引用 → React 跳过重渲染）；键集变化也算变化，避免留下上一个模式的陈旧键。

**更正**：外部评审把 `Maximum update depth exceeded` 归因于这个 effect（"每次都返回新对象"）。
复核发现**归因错误** —— 崩溃栈里根本没有这个 effect：

```
handleSliderChange (ParamControl.tsx:118)
  → handleParamControlChange (AnimationPage.tsx:605)
    → updateParam (useAnimationStore.ts:34)
      → zustand setState → React useSyncExternalStore 的 forceStoreRerender
        → enqueueConcurrentRenderForLane → getRootForUpdatedFiber → throw
```

真实成因：**连续 50 次以上的 store 更新快到 React 来不及完成一轮渲染**，命中 React 的嵌套更新上限。
实测三种输入节奏（内轨 a₁ 上左右交替 85 次）：

| 输入方式 | 结果 |
|---|---|
| 85 次排队零间隔注入 | 触发 update depth |
| 85 次逐次 await | 不触发 |
| 85 次 × 16 ms（≈60 Hz） | 不触发 |

即真实键重复（≈30 Hz）与指针拖动都复现不了；只有脚本一次性灌事件才会。

因此：本次短路修的是「父级每次重渲染都白推一轮 ParamControl」这个真实浪费，
**不宣称它修掉 update depth**。要减小那条触发面，应在 store 层对"值未变"的 `updateParam`
直接返回原 state（zustand 对相同引用不发通知），属另一件事，未擅自改。

## 五、修法四：`RelationChart` 的 point 标记方位

`axis:'point'` 的标签原先固定画在点右上 `(+6,−6)`。对**上升直线的中间点**而言，
右上方正是直线的延伸方向 —— 开普勒 `A` 点的字母会被曲线整条穿过（3 倍放大实测）。
（原先那个 37 px 宽的「斜率 k」点注更糟，收尾 7 已删。）

新增可选字段 `labelSide?: 'top-right' | 'bottom-right' | 'top-left' | 'bottom-left'`，
默认 `'top-right'` → 全仓存量页面零行为变化。开普勒 `A` 点改 `'bottom-right'`（右下是直线下侧空白区；
该点离 Y 轴只有 3%~11% 画宽，用左侧会挤到坐标轴上）。

## 七、遗留

1. `updateParam` 对"值未变"仍会发通知（每次都会新建 `params` 对象）。store 层加一行
   `if (state.params[key] === value) return state` 可显著收窄嵌套更新的触发面，需单独批准。
2. 并集取景在拖 `a₂/e₂` 时会让整个画面平移（最多 248 px）。这是"自动取景"的固有行为，
   若要画面绝对稳定，需要改成缩小比例尺或收窄参数域，属取舍问题。
3. 外轨在极端参数下（`a₂=10, e₂=0.8`）会贴到画布左右边缘 44 px 以内，此时 `r_max` 一类外侧标签可能压边。

## 八、第三轮复核：三条外部意见的落地

三条意见经实机核对全部成立，改动与实测如下（`2286064`、`31c715e`）。

### 8.1 第三定律图的折线断在 B 前面（真缺陷）

参考行星族原写死 `a = 1.5 … 7.5`，而 `a₂` 可拖到 10：

| 参数 | 折线终点（图表本地坐标） | B 点 | 结果 |
|---|---|---|---|
| `a₂=7.5`（默认） | (204.34, 29.02) | (204.34, 29.02) | 重合 |
| `a₂=10` | (117.6, 91.7) | (205.1, 29.0) | 差 107 px，B 悬空 |

修法**没有**采用"把常数扩到 10"：那样 `maxA3` 会恒为 1120，`a₂=6` 时 B 掉到 19% 高度、右侧一片空。
改为让族跟着参数走 —— `a` 从 0 到 `max(a₁, a₂)` 取 8 等分（`a=0` 时周期为 0，首点正是原点）：

- 折线永远过原点、以"最远那颗行星"收尾，A、B 不可能脱线
- `a₂=6` 时轴缩到 `6³×1.12`，B 在 89% / A 在 38%（原先 A 只有 8%）
- 实机：`a₂ = 6 / 7.5 / 10` 三点离直线分别 0.04 / 0.00 / 0.02 px（A）与 0.02 / 0.05 / 0.02 px（B）

### 8.2 第三定律模式的竖直虚线（共焦修复引出的回归）

该线画在 `x = 0`，其实是**内轨椭圆的短轴**。改之前内、外轨都居中于原点，它恰好是两条椭圆的公共对称轴；
共焦平移把外轨挪走之后，它就只属于内轨了 —— 默认相差 36 px（456 vs 420），`a₂=10` 时线还随取景移到 504。

- 处理：`mode === 2` 不画竖线，只保留水平虚线（`y = 0` 才是两轨真正共有的长轴 —— 两椭圆中心都在它上面）
- 未采用"改成过太阳"的方案：过焦点的竖线对两条椭圆都不是对称轴，会制造另一种错觉
- 实机：模式 0/1 仍有 1 条贯穿画布的竖线（x=420）；模式 2 为 0 条

### 8.3 周期与偏心率无关，应当点破

实测 `e₁` 从 0 拖到 0.85：右屏 `内轨 a₁ / T₁` 恒为 `4.5 / 10.00`，图上 A、B 两点与折线终点像素级不动。

- 第三定律模式的高考要点新增一条：「同一中心天体的椭圆轨道，周期只由半长轴 a 决定，与偏心率 e 无关……」
- 左屏教学提示补半句：「偏心率 e 只改轨道扁平程度，T 与 k 完全不变。」
  （`check-control-meta` 的 85 字上限只约束 `type:'preset'`，不约束 `type:'tip'`）
