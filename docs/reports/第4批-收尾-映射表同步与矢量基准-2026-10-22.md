## ② 平抛页分速度箭头长度恒定（B）

### 诊断（跑页面，不靠符号推断）

平抛页 `ProjectileAnimation` 只给 `velocity` 配了 `refMagnitudes`，而 `ProjectileScene` 用 `type="velocityX"` / `"velocityY"` 画了两个分速度箭头。`refMagnitude` 取到 0 → `calculateVectorPixelLength` 直接 `return minLength`（14px）并每次渲染告警一次。

修改前的 DOM 实测（t=0，抛出瞬间）：`vₓ` 箭头的直线段 7 px（总长 14 px = `minLength`），`v` 箭头直线段 81.5 px；`v_y` 在 t=0 时为 0 被隐藏。`vₓ` 的 14 px 是 `calculateVectorPixelLength` 在 `refMagnitude<=0` 时的固定返回值，**与速度无关**，所以任意时刻都是 14 px；同时控制台有 10 条 `[vectorLength] "velocityX" 的 refMagnitude 未配置` 告警。

后果是画面上等于在说「vₓ 和 v_y 都不变」，而平抛的核心恰恰是「vₓ 恒定、v_y 线性增长」——一半对一半错，比全错更容易误导。

### 基准怎么定（三次试错，前两次都不成立）

箭头长度公式：`len = min(|v| / ref, 1) · maxLen · weight`，而 `velocityX/Y` 的 weight 是 0.8，`velocity` 是 1.0。

| 方案 | 结果 |
|------|------|
| 三者配同一 ref | 分量被权重额外压短 20%，两个分量的长度和短于合速度，**三角形接不上**（t=1.4 实测：vₓ 45.3、v_y 62.2，和为 76.9，而 v 箭头 96.2，短 20%） |
| ref 只按「最大分量」配 | 当两分量接近时 `v` 超过 ref 撞上 `min(…,1)` 截断，**末段又裂开**（v₀≈14 时必现） |
| ref 按分量峰值且与合速度保持权重反比 | 全程不截断、三角形精确闭合 ✅ |

最终规则（写成可测的纯函数 `src/utils/vectorRefs.ts`）：

```
ref_component = max( 全程最大分量 , 全程最大合速度 × weight_component/weight_main , 0.1 )
ref_main      = ref_component / (weight_component/weight_main)
```

- `weight_*` 从 `VECTOR_VISUAL_WEIGHT` 读取而非写字面量 0.8，权重表调整时不会失配；
- 兜底 0.1 防止退化参数（v₀=0）重新触发 `ref=0` 回退与告警。

|------|------|

## ③ 斜抛页非等比缩放：轨迹方向与 θ 标称不一致

### 诊断

`anchor:'viewport'` 会按 `physicsWidth`/`physicsHeight` 各自撑满视口，x/y 两轴缩放比通常不等。该页的 `physicsWidth/Height` 是「射程×1.15 / 最大高度×1.35」，与画布的 840×325 宽高比无关，于是：

| 画法 | 使用的坐标 | 是否受两轴缩放影响 |
|------|-----------|-------------------|
| 轨迹（`worldToDesign`） | 物理→设计，x/y 各自缩放 | **是** |
| 炮筒、扇形、`θ = xx°` 标注 | 屏幕空间（`rotate(-θ)`、`cos/sin`） | 否，恒等于 θ |
| 速度矢量箭头（`normalize(vector)`） | 屏幕空间 | 否，方向恒等于真值 |

三者互相矛盾。默认参数（v₀=20 m/s、θ=45°）下实测轨迹起始方向 **48.6°**，而炮筒与标注都是 45°；更关键的是「速度方向 = 轨迹切线方向」这条本页要教的关系在画面上不成立。

顺带发现告警本身的判据也有问题：`scaleX !== scaleY` 用严格浮点判等，等比场景下两轴走不同计算路径会得到 `9.285714285714285 / 9.285714285714286`（差 1 ULP），于是每帧、每个箭头各刷一条告警（6 条/帧），把真正的告警淹掉。

### 改法

**比例尺（`ObliqueThrowAnimation.tsx`）**：让物理窗口与画布同宽高比，`scaleX === scaleY`。

```
viewAspect   = vp.visibleW / vp.visibleH
targetWidth  = max(needWidth, needHeight × viewAspect)
targetHeight = targetWidth / viewAspect
```

由此 `worldH = worldW/aspect ≥ needHeight`、`worldW ≥ needWidth` 恒成立，**量程不会溢出**（射程≤worldW、最大高度≤worldH），也不需要额外裁剪。`viewMode === 1`（固定 100 m）仍保持 100 m 宽，只是高度按比例补到 38.7 m。

**告警判据（`VectorArrow.tsx`）**：抽出 `isNonUniformScale(scaleX, scaleY, relTol = 1e-6)` 用相对误差判等；同一组缩放比只告警一次（模块级 Set，上限 20 组），避免刷屏。`intentionalNonUniformScale: true` 的 4 个示意类场景（切割磁感线、线圈过场、圆周几何、机械波）行为不变。
