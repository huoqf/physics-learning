## 一、三个"在讲错话"级别的问题

改之前，这一页有三处不是画得不好，而是逻辑上不成立：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `KeplerAnimation.tsx` 模式 0 | 「第一定律验证：r₁ + r₂ = 2a」中 `r₂ = 2a − r₁`，两式相加恒等于 2a。椭圆的 b 算错、焦点位置错、甚至把轨道画成圆，这个数都不会变。**它验证的是算术恒等式。** |
| 2 | `useKeplerPhysics.ts` | `T₂ = T₁·√(a₂/a₁)³`：外轨周期由第三定律反推，那么 T²–a³ 图上的"直线"是恒等式而非数据。同时 `k = T₁²/a₁³` 会随 `T₁` 滑杆变化（5→20 s 变化 16 倍）、随 `a₁` 变化（2.5→5.5 变化 5.8 倍）—— **页面上没有任何一个操作能让 k 保持不变**，而"k 不变"正是这节课要教的。 |
| 3 | `KeplerAnimation.tsx` 模式 1 | 「扫过时间占周期百分比 12%（恒定）」直接打印 `KEPLER_CONFIG.sweepTimeRatio` 这个常量本身。面积相等由构图保证，没有任何量被测量过。 |

## 二、物理层：以 (a, e, GM) 为输入的单一真源

`src/physics/celestial.ts` 新增：

| 导出 | 作用 |
|---|---|
| `solveOrbitCore(a, e, t, period)`（私有） | 唯一的轨道求解实现；`b` 由 `b = a√(1−e²)` 派生 |
| `calculateKeplerOrbit(a, b, t, period)` | 改为**委托** core：`e ← √(1−(b/a)²)`。消除原先"celestial 与 useKeplerPhysics 各推导一遍 c、e"的双真源 |
| `ellipseFromEccentricity(a, e)` | 一次给出 b / c / rMin / rMax |
| `orbitalPeriodFromMass(a, mass, G)` | `T = 2π√(a³/GM)` —— 第三定律的**动力学来源**，不是它的推论 |
| `specificAngularMomentum` / `arealVelocity` | h = √(μa(1−e²))、dS/dt = h/2 |
| `orbitLegality(a, e, minClearance)` | 把"这个参数组合物理上是否存在"变成显式返回值 |
| `evaluateKeplerOrbit(a, e, mass, t)` | 中屏与看板共用同一函数取 r / v / period / h |
| `sampleSweptArea(a, e, mass, samples)` | 逐段三角形**数值累积**扫过面积；内部积分步长 = samples × 16（见 §五.2） |

`b > a` 从此不可表达：几何由 e 派生，非法参数从源头消失，而不是靠 `Math.max(0, a²−b²)` 静默吞掉。

## 三、参数层：`b₁ / T₁` → `e₁ / M`

`registries/mechanics-circular-gravitation.ts`：

```
旧：a(2.5~5.5)  b(1.5~4.5)  period(5~20)   a2(6~10)  b2(4.5~9)
新：a(2.5~5.5)  e(0~0.85)    mass(10~80)   a2(6~10)  e2(0~0.8)
```

- 周期不再可调，由 `T = 2π√(a³/GM)` 派生（G = 1，与双星模型 `CELESTIAL_SIM_G` 同一约定）
- 于是 **k = a³/T² = GM/4π²**：拖 a 不动 k，拖 M 才动 k
- 默认值取 `a=4.5, e=0.75, M=36` → `T₁ = 9.997 s`、`k = 0.9119`，与旧版 `T=10 / k=0.9113` 几乎一致（默认画面观感连续）
- 左屏加了一张教学提示卡说明"周期不是独立旋钮"

看板（`data/quantities/gravitation.ts`）改为调用同一套物理函数，不再自己推导 c / e / T / T₂：

- 模式 0 新增「焦半径之和(实测)」= `hypot(r₁) + hypot(r₂)`，与 `=2a` 并列
- 模式 1 新增「r·v（近日点）」/「r·v（远日点）」两行，两值相等
- 模式 2 新增「中心天体质量 M」，k₁ / k₂ 由同一个 T 计算

## 七、遗留

1. **`ParamControl` 的 effect 隐患（既有，非本次引入）**
   `src/components/UI/ParamControl.tsx` 里 `useEffect(() => setLocalValues(...), [params, paramsSignature, editingKey])` 无条件返回新对象，`params` 引用一变就再渲染一次。表现为：对同一个滑块连续合成 85 次 ArrowRight（Playwright 不带间隔）会抛
   `Maximum update depth exceeded`，栈落在 `useAnimationStore.updateParam → forceStoreRerender`。真实拖动与正常键速（含 40 次连续）均不触发。修它要动 124 页共用的控件，需单独批准。
   本次把 e 的步长从 0.01 调到 0.05（17 档），把一个可达的触发面顺手收窄，但根因未除。

2. **极限参数的画面拥挤**：a=2.5 时椭圆只有 160×85 px，r₂ / 副焦点 F₂ / 行星 / v 四个标签互相压。要根治得接 `src/utils/layoutLabels.ts`（纯函数避让，全仓仅 2/124 页在用），属另一件事。

3. **第三定律的"行星族"仍是示例点**：7 个 a 由同一 M 派生，本质仍是"给定模型 → 得到直线"。真正不可自证的做法是让第三个速度/周期独立可调，但那会引入与 M 冲突的第二个自由度，教学上不划算，故保留"示例族"并在图上标为参考。

4. **模式 2 的行星 B 没有速度箭头**（`v` 只画行星 A），"高轨低速"仍靠周期读数间接体现。

5. **`PhysicsVectorArrow` 仍只有线性映射**：本页的引力量程 47:1 靠收尾6 的几何封顶处理，未引入非线性档位。`GravityAnimation.tsx` 里手搓的 `15 + log10(F+1)*15` 依然是同类需求的第二处孤例。

6. **`RelationChart` 的 point 标记标签固定画在点右上 (+6,−6)**（`RelationChart.tsx:366-376`），对上升直线必然压线：
   - 本页原来那个「斜率 k」标记（37 px 宽文字）被直线整条穿过去，3 倍放大实测糊字，**已删除**——
     斜率含义由标题「a³ - T²（斜率 = k）」与左上角 `k = a³/T² = …` 公式行承担，不再需要点注。
   - 但 `A` 点（`t2_1, a3_1`）在直线中段，`+6/−6` 正好顺着上升方向，字母被曲线穿过；
     `B` 在直线末端所以没事。1 倍实拍确认 A 有"被划掉"的观感。
   - 这是**全仓通用约定**（`OhmLawCenterExtra` / `MomentumAnimation` / `ClosedCircuitCenterExtra` 等 10 余处
     上升曲线的点注都是同一形态），单改本页会与其他页不一致，故未动。
   - 根治办法：给 `RelationMarker` 加一个可选的 `labelAnchor?: 'start' | 'end'`（默认 `'start'`，
     零行为变化），上升直线取 `'end'` 让文字落在点的左下方空白区。属共享组件改动，需单独批准。
